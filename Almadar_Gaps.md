# @almadar/ui — open gaps

Every open gap this repo owns lives here. This file is the source of truth; the monorepo's `docs/Almadar_Gaps.md` only rolls it up.

- **One entry per gap:** `- **<code>** — <what is wrong and where>. <owning package> [mechanical|architectural] — <evidence, prevention rung>`. `[mechanical]` = small and well-scoped; `[architectural]` = needs design judgment.
- **Codes:** new gaps use this repo's prefix `G-UI-`. Take the "Next code" below, then bump it in the same edit. Codes are never reused or renamed.
- **Close by deleting.** Remove the entry in the same commit as the fix. There is no "closed" section; git history is the record.
- **Cross-repo gaps don't go here.** If fixing it needs another repo, describe it in your report or PR body; the monorepo coordinator files it.

## Open gaps

- **G-UI-045** — The visual gate renders `ui-*` behaviors with placeholder fixtures ("Name", "Label", one row), so empty, loading, error and full-data variants, long text and 320px wrapping are never exercised; the 2026-09-30 audit found clipping and dead states only by hand-built fixtures. Add realistic per-pattern fixtures (loading/error/empty/full) to the gate. `scripts/` gate [mechanical] — found 2026-09-30
- **G-UI-044** — `scripts/component-contrast-audit.mjs` (the real text/background pairs components render) fails 7 pairs in 4 theme modes, so it is not yet wired into `verify:themes`. game-adventure-dark / game-ui-pack-dark (and a third game dark mode) pair light "parchment" cards and a light `muted` with a light `foreground`, so `text-foreground on bg-muted` is 1.13:1; the pairs cannot all pass while the dark variant keeps light cards (muted-foreground must read on both card and muted). win95-light puts white `foreground` (made for the teal desktop) on warning/secondary/muted tints (2.8–4.4:1). Fix is theme data in `@almadar/core/themes/*.json` (dark cards in dark variants, or a dark foreground on tinted surfaces) then regenerate themes; then add `node scripts/component-contrast-audit.mjs` to `verify:themes`. [owner-decision] — changes the look of those themes; found 2026-09-30; prevention rung: the audit itself, once gated
- **G-UI-040** — `List` picks its row Edit/View buttons by matching action LABELS (`label.toLowerCase().includes("edit"/"view"/"open")`) and demotes every other action to the overflow menu, so an action's placement depends on its wording, not a declared contract. `components/core/organisms/List.tsx` `defaultRenderItem` [mechanical] — found 2026-09-30 while adding `when`; prevention rung: `.lolo` type (a declared placement member on the action item).
- **G-UI-038** — Status text painted on the surface tint fails WCAG AA in most themes: `Badge` (`bg-surface text-warning`, likewise success/error/info), `Alert`, `Toast` and ~150 other `text-{success,warning,error,info}` sites use the status FILL color as text. On 2026-09-30, 56 of 108 theme modes failed at least one of these pairs; warning yellow was worst (1.06:1 in zine-light). Darkening the tokens is wrong because it turns every warning fill brown. Needs a design call: filled status badges (`bg-warning text-warning-foreground`, already audited), or a new `*-text` token per status in `ColorTokens` + `themeTokensToCssVars` + theme.rs. The contrast audit gates it once decided. `components/core` + `@almadar/core` ColorTokens [owner-decision] — found 2026-09-30 theme range program; prevention rung: the contrast audit (`scripts/theme-contrast-audit.mjs`) checks only token pairs, not the pairs components actually paint

- **G-UI-037** — Two line-chart renderers: the `LineChart` molecule (`components/core/molecules/LineChart.tsx`) and `Chart`'s internal line/area renderer (`Chart.tsx`). They diverged: only `Chart` has a labelled value axis, multi-series and period-aware time labels, and only `LineChart` spaces a numeric `x` proportionally. Both needed the same lone-point fix on 2026-09-30. Converge to one renderer (`Chart` look `line`/`area`, gaining numeric-x spacing), with `LineChart` as a thin wrapper or retired from the pattern registry, which needs the patterns → core → lolo-ui chain. Prevention rung: none of the three (a duplicate component). `components/core/molecules/{Chart,LineChart}.tsx` [architectural]
- **G-UI-036** — In the `kiosk` theme the toolbar search input truncates its own placeholder at phone width ("Searc…" at ~190px): kiosk's 26px icon size plus input padding leaves little text room. Size the leading-icon padding from the icon token instead of a fixed `pl-10`, or cap it for large icon themes. `components/core/atoms/Input.tsx` [mechanical] — found 2026-09-30 responsive sweep

- **G-UI-032** — `UISlotRenderer`'s `modal` slot (`components/core/organisms/UISlotRenderer.tsx` ~L420–480) draws its own overlay + box + ✕ button instead of the `Modal` molecule, so a slot modal has no `role="dialog"`, no `aria-modal`, no focus trap and none of `Modal`'s mobile sheet behaviour. Found 2026-09-29: std-list's Create form on a published app is not reachable as a dialog (`getByRole('dialog')` finds nothing). Converge the slot onto `Modal`. Prevention rung: none of the three (an accessibility contract; a jsdom a11y assertion on the slot would pin it). `@almadar/ui` [mechanical]
- **G-UI-031** — `Stack` (and so `VStack`/`HStack`, `components/core/atoms/Stack.tsx`) and `Typography` forward only a fixed prop list, so `data-*` and `aria-*` attributes written on it type-check (JSX allows any `data-*`) yet never reach the DOM. Test ids and ARIA on stacks silently vanish; found 2026-09-29 when the Studio publish panel's `data-testid`s on VStack rows were missing (moved to `Box`, which forwards `...rest`). Fix: forward `data-*`/`aria-*` like `Box` does. Prevention rung: 1 (the props type should declare what is forwarded, so an undeclared attribute is a type error). `@almadar/ui` [mechanical]
